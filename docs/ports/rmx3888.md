# RMX3888 experimental port status

This branch is a build/configuration probe, NOT a flashable recovery release.

## Verified evidence
- Running Android device: realme RMX3888 / RE5C37, project 23607, SM8650.
- System build: RMX3888_16.0.3.500(CN01), Android 16.
- Physical display: 1264x2780, density 560.
- Touch controller: /proc/devinfo/tp reports SY_BOE, firmware tp/23607/FW_S3910_BOE.img.
- spi0.0 driver is synaptics-s3910; its module is oplus_bsp_tp_tcm_S3910.
- Wi-Fi module observed: qca_cld3_kiwi_v2; supplicant exists at /vendor/bin/hw/wpa_supplicant.
- recovery_a and recovery_b: identical SHA256 cc34cd71ce185f77b6c996fd33df83ddb7db7d0c24372953e90a09099cc3f492, each 104857600 bytes.
- Recovery image: header v4, zero embedded kernel, legacy LZ4 ramdisk, AVB footer. Both partitions contain TWRP resources.
- userdata and metadata: F2FS. Userdata encryption flags: aes-256-xts:aes-256-cts:v2+inlinecrypt_optimized+wrappedkey_v0; metadata aes-256-xts:wrappedkey_v0.

## Important incompatibilities
1. The upstream packer intentionally rejects twres/FFiles. This protection has NOT been removed.
2. TWRP init waits for twrp.modules.loaded=true before mounting firmware, starting ADSP/health and variant-script. That property is normally supplied by TWRP, not Android init. Replacing the recovery binary can leave this chain permanently waiting.
3. The variant script then sets twrp.variant.files_copied=1, which starts prepdecrypt, vibrator, secure element, NXP weaver and OMAPI. The script does not explicitly recognize project 23607. The user's functioning TWRP is the reference, not proof that all services can be reused by Skyward.
4. prepdecrypt unmounts system/vendor/odm and rewrites version properties; blindly starting it alongside Skyward's own mounting and version adoption would race.
5. NXP secure-element/OMAPI and weaver startup need investigation before claiming FBE unlock. TWRP's working decrypt implementation is not inherited by a replacement Rust binary.
6. twrp.flags labels metadata ext4, whereas the actual filesystem and recovery.fstab say F2FS. Do not copy that override.
7. Boot properties report locked/green despite custom kernel/root/TWRP. Actual bootloader state must be established outside spoofable properties before testing.

## Next stages
- Obtain factory recovery matching this firmware, OR implement an explicit TWRP-base port with separate lifecycle management and tests, not a blanket bypass.
- Validate module and firmware loading in the recovery kernel environment; running Android's kernel is not proof of compatibility.
- Map the TWRP HAL service dependency graph and compare against Skyward's AIDL clients.
- Prove display and input first, then storage and decrypt. Do not test wipe, restore, partition flashing or second-system operations until recovery/rollback is verified.

No device image, ADB keys, private properties, userdata or other personal material is uploaded by this branch. Only configuration, tests and these technical findings are committed. No factory OTA URL or checksum is invented.
